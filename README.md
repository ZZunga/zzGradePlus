# zzGradePlus

Edge 540 / 840 / 1040 / 550 / 850 / 1050 / 1060 용 경사도 데이터 필드.
SDK 9.3.0, 타입 체크 Strict(-l 3)로 7개 기종 모두 빌드 확인.

## 경사도 계산 (기존 zzGrade 방식 + 개선)
1. 매초 현재 속도(m/s)를 누적 → 3초간 이동거리
2. 3초마다: g = (지금 고도 - 3초 전 고도) / 3초간 이동거리
3. 최근 N개 g의 이동평균 (설정 "경사도 평균 구간", 1~5, 기본 3 = 약 9초)
4. 3초간 이동거리 3 m 미만 또는 속도 0.5 m/s 미만이면 정지로 판단
5. 필터 결과 절댓값 50% 이상은 버림
6. 표시: 10% 미만 소수 한 자리, 10% 이상 정수

개선한 점
- 매 구간 정확히 속도 3개 누적 (기존: 첫 구간은 2개)
- 재출발 후 첫 계산값으로 필터를 채워 바로 실제 경사도 표시 (기존: 0부터 약 9초에 걸쳐 상승)
- 정지 중 마지막 경사도 유지 (기존: 0 표시)

## 설정
- 앱 버전 (읽기 전용)
- 경사도 평균 구간: 1(3초) / 2(6초) / 3(9초, 기본) / 4(12초) / 5(15초)
- 메인 값(큰 글씨): 경사도(기본) / 고도 / 총 획득고도 / Lap 획득고도
- 두 번째 값(작은 글씨): 경사도 / 고도 / 총 획득고도(기본) / Lap 획득고도 / 없음
  - 두 설정은 같은 목록을 쓰며, 둘이 같은 값이면 두 번째 값을 자동으로 바꿔서 저장한다
    (메인이 경사도면 고도로, 메인이 고도 계열이면 경사도로)
- 배경색: 기기 화면색에 맞춤 / 검정·흰색 그대로(기본) / 투명
- 색상 기준 경사도(%): 기본 1 → +1% 초과 오르막 색, -1% 미만 내리막 색
- 주간/야간 오르막·내리막 색 (색상표 인덱스는 다른 zz 앱과 동일, 배포 후 순서 변경 금지)
- 고도 단위(m/ft)는 기기 설정(elevationUnits)을 따름

## FIT 기록
- "Grade" 필드, FLOAT, 단위 %, record 메시지, 1초마다 (기존 zzGrade와 같은 이름/형식)
- manifest에 FitContributor 권한 포함

## 화면
숫자 크기는 칸에 실제로 몇 자리가 들어가는지 `onLayout`에서 재서 정한다 (`fitDigits`).
글자 수를 고정해두면 경사도(길어야 3글자)에는 맞고 고도(4~5자리)에는 넘친다.

글꼴 사다리 — 칸에 들어가는 가장 큰 것을 쓴다. 넷 다 바닥선을 맞춰 두었다.
1. `C10Main` 경사도용
2. `C10Main4` 10필드 칸에서 4자리 고도가 꽉 차게 (base 30 / 36 / 51 / 59)
3. `C10MainDec` 소수점용
4. `C10Sub` 3열 레이아웃 같은 좁은 칸

그래도 안 들어가면 순서대로:
- 단위(m/ft)를 숨긴다 — 라벨에 단위가 적혀 있다
- 천 단위로 바꾼다 — `12345 m` → `12.3 km`, `12345 ft` → `12.3 kft`

그 밖에
- 넓은 칸 제목은 `zzGrade+` (앱 이름은 zzGradePlus 그대로). 라벨과 겹치면 제목을 생략한다
- 값이 왼쪽까지 밀고 들어오면 좌상단 산 아이콘을 생략한다
- 단위 자리는 `ft`와 `m` 중 넓은 쪽 기준으로 비워둔다 (미터법에서 `m`이 1px 더 넓다)
- 아이콘: grade.svg를 '@' 글리프로 포함, 녹색 (기존 zzGrade와 같은 색)

## 배경색 — Edge 1050 / 1060
데이터 필드 배경을 검정·흰색으로 칠하면 1050/1060에서는 네이티브 필드와 색이 어긋난다.
`getBackgroundColor()`는 `COLOR_WHITE`와 `COLOR_BLACK`만 돌려주고, 실제 색을 알려주는 API는 없다.

포럼 "Background color of EDGE 1050" (discussion/382055) 에서 나온 값:

| | 값 | 출처 |
|---|---|---|
| 어두운 배경 | `0x17181D` | 기기 리소스 파일 Rez.mir, system / activity 상태 — **지금 쓰는 값** |
| 어두운 배경 | `0x101819` | 실기기 스크린샷 실측 (네이티브 필드) |
| 어두운 배경 | `0x191919` | Rez.mir, prompt 상태 |
| 밝은 배경 | `0xDCDCDC` | Rez.mir, 세 상태 모두 — **지금 쓰는 값** |
| 어두운 글자 | `0xFFFBFF` | 실측. 순백과 차이가 거의 없어 `COLOR_WHITE` 유지 |
| 밝은 글자 | `0x313152` | **근거 없음.** 포럼에 측정치가 없다 |

Garmin 쪽 답변은 "1050의 색은 바뀌지 않을 것"이며 CIQ 팀에 티켓이 올라가 있다.
색을 맞추는 건 결국 추측이고 펌웨어가 바뀌면 또 어긋나므로, **투명(bgMode 2)이 근본 해결책**이다.
배경을 칠하지 않으면 기기가 깔아놓은 배경이 그대로 비쳐 테마가 무엇이든 일치한다.

주의 — `soft` 경로(`screenWidth >= 480`, 즉 1050/1060)는 **실기기 검증이 안 되어 있다.**
보유 기기가 Edge 1040(282x470)뿐이라 자동 모드의 색 값들은 시뮬레이터와 포럼 수치에만 근거한다.
투명 모드는 모든 기기에 적용되므로 1040에서 검증할 수 있다 (숫자 번짐·잔상 여부).

## 업로드 전
- manifest.xml application id는 임시 UUID. 기존 zzGrade를 업데이트한다면 기존 앱의 UUID와 개발자 키를 사용할 것.
